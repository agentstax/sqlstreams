Message-log partition count produced by the metrics collector, independent
of alert checks and their thresholds.

The `topic` attribute identifies the topic. For `orders`, the message key is
`vulkan.topic.state.partitions|topic=orders`.
Compaction uses rank zero, so the highest message id becomes the head.
Each stored message carries its database `CreatedAt` timestamp. Earlier
observations remain subject to metrics retention.

Partition-count alerts read the retained metric; they do not produce it.
Missing evidence fails the check instead of resolving an alert. Registration
warnings use the same retained value and may report missing evidence before
the first collection. Pending-duration and freshness-window evaluation remain
[Proposed](/concepts/alert-history/).
