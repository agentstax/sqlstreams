Raw partition count read by the scheduled partition-count alert check,
including healthy counts and checks that produce no alert.

The attributes are `alert=partition_count` and `topic_id`. For topic `orders`
with id 41, the message key is
`vulkan.alert.observed_partitions|alert=partition_count,topic_id=41`.
Compaction uses rank zero, so the highest message id becomes the head.
Each stored message carries its database `CreatedAt` timestamp. Earlier
observations remain subject to metrics retention.

The observation is stored before alert recording. A failed alert write does
not remove it; a retry reads the source again. Registration-time warnings
do not store observations. Pending-duration evaluation remains
[Proposed](/concepts/alert-history/).
