---
title: "vulkan.otel.source.read_success"
slug: errors/VK0102
kind: "metric"
consequence: "attribute-free gauge; 1 when the current adapter collection read succeeds, 0 when it cannot complete"
---

The adapter records whether this collection read retained measurements
successfully. Empty results count as success. This gauge is computed by the
adapter and is never written to the metrics topic.

Prometheus exposes `vulkan_otel_source_read_success`. A scrape can return
HTTP 200 with this value at 0; check the gauge as well as HTTP availability.
On a read failure, no retained measurement values or rejection count accompany it.

The gauge requires the reader to call Vulkan's producer. An already-canceled
ManualReader call stops before that point and returns no health gauge. A read
that reaches Vulkan but exceeds its CollectTimeout returns 0 with the error.

For example, installation `billing` loses its database connection: a scrape
can still succeed, but the gauge reports 0. After the next successful read it
reports 1. A 1 says nothing about the age of the retained observations; use
[collector progress](/errors/VK0101/) for collection liveness.
