---

Message-log partition count produced by the metrics collector, independent
of alert checks and their thresholds.

The `stream` attribute identifies the stream. For `orders`, the message key is
`sqlstreams.stream.state.partitions|stream=orders`.
Compaction uses rank zero, so the highest message id becomes the head.
Each stored message carries its database `CreatedAt` timestamp. Earlier
observations remain subject to metrics retention.

Partition-count and compaction-read-cost alerts read this retained metric;
they do not produce it. `Metadata.compaction_status` records `compacted` or
`uncompacted` from the same snapshot as the count. Missing evidence cannot
resolve an alert. Registration warnings use fresh retained evidence without
pending; scheduled checks use the shared [pending rules](/reference/alerts/#gotchas).
