---
title: "could not claim messages"
slug: errors/SQL0108
kind: "event"
level: "warn"
consequence: "the next claim waits one poll rate"
---

A consumer instance's claim did not land and the datastore retry curve
is spent, so the instance waits `ConsumeOptions.ClaimPollRate` and claims
again. Nothing is lost - a range that was never leased is taken by the
next claim, and an exception row whose outcome did not record rides out
its lease. The `worker` attribute names which of the group's two rows
hit it, `delay` is the wait, and `error` carries the joined attempts.

Only a transient cause reaches this line: a dropped connection, a
deadlock, a Postgres restart. A cause an unchanged retry cannot fix -
a missing cursor row, a revoked grant, a permanent error code - ends
`Consume` with that error instead, so a consumer with a broken claim
path stops rather than polls forever looking alive.

One line is a blip. The same line repeating means the database is
reachable and rejecting every claim in the same way; look at the
`error` attribute for the SQLSTATE and at Postgres for connection
limits or a restart loop.

Repeats of this line inside a one-minute window collapse to the first,
and the next one carries the dropped total as `suppressed_count`.
